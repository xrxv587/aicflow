# 命令参考

[← 返回首页](./Home.md)

通用约定：所有命令以 **`process.cwd()` 为项目根**，不会向上查找父目录；断点文件固定为 `.ai-continue/current.md`。

---

## `aic init [任务名] [-y]`

初始化断点文件，并把 AI 引导注入项目的引导文档。

流程：

1. `readCurrent` 发现已存在 `current.md` → 打印当前任务名（结构损坏时打印"（结构异常，见 aic status）"），**直接返回，不覆盖**（退出码 0）。
2. 任务名来自参数；未给且非 `-y` 时交互询问。最终为空 → stderr 报错，退出码 1。
   注意：**`-y` 不提供默认任务名**，它只跳过询问；`aic init -y` 不带任务名照样报错。
3. `writeCurrent(renderTemplate(task))` 创建 `.ai-continue/current.md`（模板含初始 `updated`）。
4. 进入引导注入流程（详见 [guide-injection](./guide-injection.md)）：
   - 无任何候选引导文件 → 确认后创建 `AGENTS.md` 写入引导；拒绝则把引导全文打印出来让用户手动粘贴。
   - 有候选 → 跳过已含标记的文件；多个待注入且非 `-y` 时让用户选序号（直接回车默认第一个）；单个且非 `-y` 时确认追加。
   - `-y` 时全部跳过询问，多个待注入则静默选第一个。

## `aic status`

查看当前任务进度与上下文。**这是 AI 会话开始时执行的命令**，行为设计为"要么给出可继续的状态，要么给出明确的修复提示"。

输出结构：

```
任务：<task>
更新时间：<updated 或 未知>
进度：<done>/<total> 已完成（<状态>）

待办：
  [x] 已完成条目
  [ ] 未完成条目

上下文：
  <上下文内容，空则显示（空）>
```

状态字段：无待办条目 → `尚无待办条目`；全部勾选 → `全部完成，可执行 aic done 归档`；否则 → `进行中`。

结构校验失败时（退出码 2）逐条打印 `parse` 的错误信息，指引修复 `current.md`。

---

## `aic done [-f | --force]`

归档当前任务：把 `current.md` 移动到 `.ai-continue/archive/YYYY-MM-DD_HHMMSS-<安全化任务名>.md`。

流程：

1. 未初始化 → 报错退出（退出码 1）。
2. `parse` 结构异常且非 `--force` → 打印错误，退出码 2。
3. 有未完成待办且非 `--force` → 列出未完成项并 `confirm`（默认 N）；取消则打印"已取消。"正常退出。
4. 归档并打印目标路径，提示可用 `aic init [新任务名]` 开始下一个任务。

`--force` 同时跳过结构校验和未完成确认；结构损坏时归档文件名任务段回退为 `task`。

---

## 退出码矩阵

| 命令 | 0 | 1 | 2 |
|---|---|---|---|
| `init` | 正常完成 / 已初始化跳过 / 用户拒绝注入 | 任务名为空 | — |
| `status` | 正常输出 | 未初始化 | 断点文件结构异常（附修复提示） |
| `done` | 归档完成 / 用户取消归档 | 未初始化 | 结构异常且未 `--force` |
| 任意 | — | 顶层未捕获异常（仅打印 message） | — |

退出码是给 AI 客户端看的协议：`1` = 没有任务可续，`2` = 断点文件坏了需要先修。修改任何命令时**不要破坏这套语义**。
