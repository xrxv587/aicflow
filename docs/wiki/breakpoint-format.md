# 断点文件格式规范

[← 返回首页](./Home.md)

文件位置：`.ai-continue/current.md`；归档后移动到 `.ai-continue/archive/`。格式为「Markdown 为主 + 少量固定结构」，解析器是 `src/core/breakpoint.ts` 的 `parse()`。

## 合法示例

```markdown
---
task: 重构登录模块
updated: 2026-09-29 14:30
---

## 待办
- [x] 拆出 API 层
- [ ] 处理 token 刷新

## 上下文
决策、踩坑、涉及文件等，自由 Markdown。
```

## 结构规则

### frontmatter

- 首行必须是 `---`（允许行首空白）；闭合的 `---` 必须整行精确匹配。
- 字段行匹配 `^(\w+):\s*(.*)$`，**key 仅限英数字下划线**，不支持中文 key。
- `task`：必填非空，缺失报错 `frontmatter 缺少非空 task 字段`。
- `updated`：可选，约定格式 `YYYY-MM-DD HH:mm`（本地时间）；缺失时 `aic status` 显示"未知"，不算错误。值里含冒号没问题（取第一个冒号后的全部）。

### 章节

- 以 `## 标题` 切分；**必须存在「## 待办」和「## 上下文」两个章节**，各缺一条错误。
- 其他章节允许存在，解析时被忽略（不报错）。
- 同名章节出现多次时内容合并到同一个 key。

### 「## 待办」内的行

checkbox 正则：`/^\s*-\s+\[( |x|X)\]\s*(.*)$/`

- 空行：跳过，合法。
- 非空行且不匹配正则：**报错**（这是结构异常退出码 2 的主要来源），错误信息会带上原行内容。
- 匹配但文字为空（如 `- [ ]`）：静默忽略，不算条目也不报错。
- `[x]` / `[X]` 大小写都算已完成。

### 「## 上下文」

自由 Markdown，整体 `join('\n').trim()` 收集，可为空。

## 写入约定（AI 直接编辑时）

由注入的引导约束（见 [guide-injection](./guide-injection.md)）：

- 只在「## 待办」下增删改 `- [ ]` / `- [x]` 行；
- 决策、踩坑、涉及文件写入「## 上下文」；
- 每次更新把 frontmatter 的 `updated` 改为当前时间（`YYYY-MM-DD HH:mm`）；
- 只改内容，保持 frontmatter 与两个章节的结构不变。

CLI 不提供编辑命令——编辑路径完全绕过工具，`parse` 的校验（经 `aic status`）是唯一的格式兜底。

## 归档文件命名

`archiveCurrent()` 的规则：

1. 任务名做安全化：`[\\/:*?"<>|\s]+` 全部替换为 `-`，去掉首尾 `-`，截断到 40 字符，为空则回退 `task`。
2. 文件名 = `YYYY-MM-DD_HHMMSS-<安全化任务名>.md`（本地时间，时间部分用下划连接到分钟+秒）。
3. `rename`（同项目内移动）到 `.ai-continue/archive/`，目录不存在会递归创建。

## 已知边界

- 任务名含换行会破坏 frontmatter 结构（`renderTemplate` 原样写入，`parse` 会在闭合 `---` 处出错）——目前没人拦截，传入前自行避免。
- frontmatter 里 `updated` 的格式只是约定，`parse` 不校验其具体格式。
- 中文任务名合法且会进入归档文件名（安全化只处理 Windows 非法字符与空白）。
