# AI 引导注入机制

[← 返回首页](./Home.md)

工具的"AI 怎么知道要续任务"靠的不是魔法，而是 `aic init` 时把一段引导文案**追加写进项目已有的 AI 引导文档**（CLAUDE.md / AGENTS.md 等）。文案与注入逻辑都在 `src/core/guide.ts` 和 `src/commands/init.ts#injectGuide`。

## 引导文案内容（guideText）

整段被 `<!-- ai-continue:guide:start -->` 和 `<!-- ai-continue:guide:end -->` 包围，分三部分：

1. **会话开始时**：执行 `aic status` 查看任务、进度与上下文；命令失败按提示处理；**存在未完成待办时，先与用户确认是否继续该任务，再开始工作**。
2. **阶段工作完成或会话结束前**：直接编辑 `.ai-continue/current.md`——更新「## 待办」checkbox、把决策/踩坑/涉及文件写入「## 上下文」、把 frontmatter `updated` 改为当前时间、保持结构不变。
3. **任务全部完成时**：执行 `aic done` 归档。

注意第 1 条的确认只覆盖**续做旧任务**；用户提出**新需求**时 AI 该做什么（先复述理解 / 出方案确认 / 分级门禁）目前完全没有引导，这是已记录的待决事项（见 [Home](./Home.md)）。

## 注入流程（injectGuide）

```
探测 GUIDE_FILES（顺序：CLAUDE.md > AGENTS.md > .cursorrules > GEMINI.md）
├── 无候选 → confirm「创建 AGENTS.md 并写入引导？」
│     ├── 同意 → 新建 AGENTS.md（标题 + 引导）
│     └── 拒绝 → 打印引导全文，让用户手动粘贴
└── 有候选 → 逐个 hasGuide(content) 检查（includes GUIDE_START）
      ├── 已含标记 → 打印「已包含引导，跳过」
      └── 收集 pending（不含标记的）
            ├── pending 为空 → 静默返回
            ├── 先打印将注入的引导全文
            ├── pending 多个 且 非 -y → ask 选序号（回车默认第一个，非法输入也回退第一个）
            ├── pending 单个 且 非 -y → confirm「追加到末尾？」，拒绝则跳过
            └── -y → 不询问；多个 pending 时静默注入第一个
追加时：目标末尾无换行补 \n\n，有换行补 \n（保证空行分隔）
```

## 幂等与升级（重要）

- **幂等判断是粗糙的**：`hasGuide` 只检查 `GUIDE_START` 标记是否存在于文件中。标记存在 = 已注入，不管内容是哪个版本。
- **已注入的引导不会随后续版本自动更新**：修改 `guideText()` 只影响之后的新注入；存量项目里被标记包围的区块永远停留在注入当时的版本。若未来引导规则升级（比如加入"新需求先确认"），需要设计迁移策略（例如版本化标记 + 识别旧块替换），目前没有这个机制。
- 注入是**追加**而非插入，永远写在文件末尾。

## 设计取舍

- 选择追加进用户已有的引导文件而不是强制新建，是为了适配各 AI 客户端不同的约定文件名。
- 拒绝注入时打印全文而非写临时文件，是为了让用户能直接复制，不在用户仓库里留下计划外的文件。
