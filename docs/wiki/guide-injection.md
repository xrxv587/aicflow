# AI 引导注入机制

[← 返回首页](./Home.md)

工具的"AI 怎么知道这套工作流"靠 `aic init` 把引导文案**追加进项目已有的 AI 引导文档**（CLAUDE.md / AGENTS.md 等）。文案与识别逻辑在 `src/core/guide.ts`，注入编排在 `src/commands/init.ts#injectGuide`。项目未投入使用，**没有升级机制**——引导只注入一次，改文案不会自动更新已注入的文件。

## 引导内容（guideText）

整段被 `<!-- ai-continue:guide:start -->` 与 `<!-- ai-continue:guide:end -->` 包围，五段：

1. **收到新需求时（先共识，后编码）**：复述理解、只提会改变做法的问题；小改动一句话对齐 + `aic start` 即做；大任务按序执行且每步未获确认不得进入下一步——确认目标/边界/验收 → 复制模板写 PRD、共识入「已确认」→ **PRD 用户确认** → 调研代码库写 TRD → **TRD 用户确认** → **动工闸门：确认 ≠ 动工，须用户明确许可实施** → `aic start` + 写 `spec:` 指针 → 编码。
2. **插入新需求（任务切换）**：更紧急时 `aic park` 挂起（断点与文档整组保存、可随时恢复）→ `aic start` 开新任务 → 完成后 `aic resume` 恢复原任务；**不得用 `aic done --force` 处理未完成任务**（历史看起来像"已完成"）；确定作废用 `aic done --abandoned`（历史带放弃标记）。
3. **会话开始时**：`aic status` → 存在未完成待办先确认续做，从「## 下一步」接续；status 提示有挂起任务时与用户确认是否恢复；PRD/TRD 按需再读，不开场全量读。
4. **执行中 / 阶段完成或会话结束前**：编辑 current.md（待办 checkbox、「下一步」改写为当前最要紧动作、`updated` 时间戳、除 `updated` 与建档时的 spec 指针外不改 frontmatter 与结构）；需求类发现写 PRD「未确认」，动「已确认」须先过用户；方案级调整先改 TRD；「## 备注」草稿区许可（未走通的尝试记 1-3 行，恢复时先核对再采信）。
5. **任务全部完成时（先验收，后归档）**：待办全勾 ≠ 完成——按 PRD「已确认 · 验收标准」逐条自检并把结果与证据写入「## 验收」区 → 向用户输出验收报告 → **获用户明确认可后** `aic done --accepted`；无文档的小任务一句话核对后直接 `aic done`。

## 识别与注入

- `scanGuide(content)` 返回三种状态：
  - `none`：文件里没有引导 → 追加目标；
  - `present`：已有引导 → **跳过**（幂等的依据）；
  - `malformed`：有 start 无 end → **跳过并警告**，绝不盲改用户文件。
- 注入 = 确认后把引导追加到目标文件**末尾**（分隔符：末尾无换行补 `\n\n`，有换行补 `\n`）。
- 多个目标文件时列出清单选序号，回车默认第一个；`-y` 静默选第一个。
- 无候选引导文件时：确认后创建 `AGENTS.md` 写入引导；拒绝则打印全文供手动粘贴。
- `aic start` 不注入引导，但检测不到引导时会打印一行提示建议 `aic init`。

## 维护注意（给本仓库维护者）

- 修改 `guideText()` 只影响**之后**的注入；已注入的文件不会自动更新。需要重新注入时，手动删除旧引导块（start..end 整段）后再跑 `aic init`。
- start/end 标记是识别锚点，措辞不可改动。
- 引导与 PRD/TRD 模板（`src/core/docs.ts`）是两份独立工件：引导讲工作流纪律，模板讲文档格式；改流程动引导，改文档结构动模板。

## 设计取舍

- 追加进用户已有引导文件而非强制新建：适配各客户端不同的约定文件名。
- 拒绝注入时打印全文而非写临时文件：用户能直接复制，不在仓库里留计划外文件。
- malformed 跳过而非追加或截断：宁可不注入，不冒改坏用户内容的风险。
- 引导是软约束（实测 AI 客户端遵守）；硬拦截只存在于 `aic done` 的验收门禁与 hooks 的 ask 上抛。恢复任务后重读 PRD/TRD 的纪律不进引导——放在 `aic resume` 的命令输出里，在动作发生的时刻递上。
